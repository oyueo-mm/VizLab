## 작업 순서와 겪은 문제

1. 3,000노드 병목 측정(메인 스레드 레이아웃 틱) → Web Worker 이전 + 링크 LOD.
2. 15개 구현(ZAME … 토네이도) → 화면 검토에서 토폴로지컬 랜드스케이프가 36개의 작은 언덕으로 지저분해 `minRise` 필터를 추가.
3. 컨투어 트리 구현에서 무한 루프(큐 재충전)와 잎 판정 오류를 고침(리프 조건 `jUp 자식 없음 + 스플릿 트리 자식 정확히 1개`).
4. 3개(백플롯·발산형 막대·결정 곡선), 다시 2개(윤곽 상자그림·스페이스트리) 추가해 340 달성.
5. 윤곽 상자그림: 엄격한 포함 기준의 띠 깊이는 윤곽이 교차하면 모든 멤버의 깊이가 같아지는 것을 데이터로 확인하고(깊이 0.1 균일), 칸 단위 수정 띠 깊이로 바꿈. 바꾼 뒤 이동시킨 멤버가 이상 윤곽으로 잡힌다.
6. 줄기-잎 그림: 자동 잎 단위가 0.5로 잡혀 줄기 레이블이 중복되는 문제 → 10의 거듭제곱 단위로 제한, 쪼갠 줄기의 둘째 줄을 중간값으로 표기.
7. 번들: React를 별도 청크로 분리(앱 청크 660 → 450 kB, 총 전송량은 +9 kB).
8. e2e에서 총 개수·카테고리별 개수·홈 단계 단언을 갱신. 신규 `e2e/v10.spec.ts`, `e2e/v10.mobile.spec.ts`. 처음 실행에서 9개가 실패했으며 모두 기대 값(개수·단계 목록)과 새 테스트의 가정 오류였고 앱 결함은 아니었다. 새 테스트의 가정 오류: 토네이도는 입력이 이미 정렬돼 있어 토글 전후가 같다, 결정 곡선의 0선은 높이 0이라 ‘보임’으로 판정되지 않는다, React의 `onPointerEnter`는 `pointerover`로 시뮬레이션해야 한다, 히스토그램 패널은 자체 연결 표식을 그리지 않는다.
9. 비동기(Worker) 결과는 `data-running` 상태를 기다려 판정하고 고정 sleep을 쓰지 않았다.

## 검증하지 못한 것 / 주의

- CI(GitHub Actions)의 성공 여부와 배포는 푸시 이후 별도로 확인한다(이 문서 작성 시점에는 로컬 결과뿐).
- 모바일은 Pixel 7 **에뮬레이션**이다. 실기기 검증은 없다.
- 연결(링크) 하이라이트: 새로 추가한 것은 백플롯(→ 산점도에서 같은 관측이 강조됨, e2e로 확인)과 걸린 루트그램(자기 막대의 왕복만 e2e로 확인, 히스토그램 쪽 표시는 확인하지 않음)이다. 나머지 새 프리셋은 같은 데이터 공유이고 호버가 전달되지 않는다.
- 서지는 웹 기록으로 확인했고 원문을 읽지 않았다(`v10-research.md`).

## 배포와 공개 사이트 확인

- 첫 푸시(`b0c416a`)는 CI의 lint 단계에서 실패했다(`vite.config.ts` 정규식의 불필요한 이스케이프 2건, `no-useless-escape`). 로컬에서는 이 파일 수정 뒤 lint를 다시 돌리지 않았던 것이 원인이다. 수정 커밋(`cea5eda`)은 CI 전체(typecheck, lint, 단위 테스트, 빌드, e2e)가 성공했고 GitHub Pages에 배포됐다(배포 확인: 공개 사이트 HTML이 `react-vendor` 청크를 참조).
