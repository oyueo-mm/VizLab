# VizLab v0.8 표현 원리 태그

카테고리(분야)·성격(방법론/전문 도표/분석 결과/응용)과 별개로, 그림이 데이터를 **어떤 시각적 인코딩·배치 원리로** 나타내는지를 태그로 붙였습니다. 값은 `src/viz/encodings.ts`에 있고 도감 상단의 ‘표현 원리’ 필터(URL `?e=`)가 이 값을 씁니다.

## 구조

- 항목마다 **주 원리 1개**(그림의 메시지를 전달하는 원리)와 **보조 원리 0개 이상**을 둡니다.
- 필터는 주 원리 또는 보조 원리에 해당하면 보입니다(상호 배타적이 아님). 칩의 숫자도 그 기준입니다.
- 전체 301개가 정확히 하나의 주 원리를 갖는지, 보조 원리가 주 원리와 겹치지 않는지는 `src/viz/encodings.test.ts`가 검사합니다.
- 태그는 사람의 판단입니다. 경계가 연속적이므로 아래 ‘경계 사례’를 함께 보세요.

## 경계 사례

- **히트맵과 인접 행렬**: 둘 다 칸을 칠하지만 히트맵은 값을 색으로(색상), 인접 행렬은 관계의 유무를 칸으로(연결) 읽는다고 보았습니다.
- **트리맵·선버스트**: 값을 면적으로 나타내지만 화면 분할이 배치 원리이므로 주 원리는 공간 분할, 보조가 면적입니다.
- **생키·앨루비얼·병렬 셋**: 양의 흐름이 메시지이면 흐름, 범주 조합의 연결이 핵심이면 연결(보조)입니다.
- **t-SNE·UMAP**: 그림은 산점도이지만 위치를 정하는 투영 계산이 핵심이어서 주 원리를 투영으로 했습니다. (성격은 ‘분석·계산 결과’.)
- **원 차트**: 값을 각도로 나타내지만 길이가 아니라 면적(각도·넓이) 원리로 보았습니다.
- **한 도표가 여러 원리를 같은 비중으로 쓰는 경우**(Flowstrates, 레인클라우드)는 복합 표현으로 두었습니다. 복합 표현은 4종뿐입니다.
- 위 판단은 사람의 판단이며 같은 항목을 다르게 분류할 수도 있습니다. 필터가 보조 원리까지 포함하는 이유가 이것입니다.
