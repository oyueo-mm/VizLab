## 작업 순서와 겪은 문제

1. 요청문 후보의 서지를 웹 검색으로 확인(17개 검색, 3개는 원 출처 미조사).
2. 엔진 먼저: `model11`(힌턴·테일러·타깃·노모그램·파이퍼·스티프·스큐-T·하세), `tree11`(피타고라스·캑터스트리·히스토리 플로), `dyn11`(행렬 큐브·간선 스플래팅·연속 산점도·연속 평행 좌표), `field11`(스폿 노이즈·스트림 리본·직사각형·이동시간 카토그램). 각 엔진은 성질 테스트로 검증: 코사인 법칙, 총점-로그 오즈 복원, 질량 보존(연속 산점도의 밀도 × 면적), 열 합 = 총 가중치(스플래팅·연속 평행 좌표), 면적 정확 비례(사각형), 나선 흐름의 비틀림(리본), 순서 공리(하세).
3. 데이터셋 11개 추가. 이미 있던 id `risk-model`과 충돌해 `nomogram-model`로 이름을 바꿈(등록 테스트가 잡아냄).
4. 윤곽 상자그림·연속 산점도 등에서 화면 검토로 발견한 문제를 수정: 연속 산점도는 퇴화 삼각형의 거대한 밀도 때문에 색이 눌려 99.8 백분위로 색 눈금을 제한, 테일러 도표 라벨 겹침 수정, 레지스트리 테스트가 요구하는 SVG 모양 수를 채우기 위해 눈금선 추가.
5. 단위 테스트에서 틀린 기대: 히세 피복 관계 수(7), 엄격한 포함 기준이 아닌 칸 단위 수정 띠 깊이 등 테스트 쪽 가정을 고쳤고 엔진은 그대로.
6. 정확도 개선 3종(`v11-inventory.md` 3절).
7. 성능: 잔여 롱태스크 조사(CPU 프로파일 → 래스터 지배), 적응형 LOD 시도·되돌림, Canvas/WebGL 비교 측정.
8. 홈 10단계, 프리셋 11개, 행 단위 연결(힌턴·파이퍼·스티프·직사각형 카토그램·링 맵·백플롯 등).
9. e2e: 신규 `e2e/v11.spec.ts`, `e2e/v11.mobile.spec.ts`. 총 개수·카테고리 개수·홈 단계 단언을 갱신. 첫 전체 실행에서 2건 실패(‘히스토’ 검색 결과 수와 텍스트 카테고리 수가 새 항목 때문에 변함)했고 기대 값 갱신 누락이었으며 앱 결함은 아니었음.

## 검증하지 못한 것 / 주의

- CI와 배포 결과는 푸시 뒤에 이 문서 아래쪽에 기록합니다. 로컬 통과와 CI 성공은 다릅니다.
- 모바일은 Pixel 7 에뮬레이션, 실기기 검증 없음.
- 서지는 웹 기록으로만 확인, 본문 대조 없음(`v11-research.md`).
- 링 맵·캑터스트리·이동시간 카토그램·스트림 리본은 원 문헌의 정확한 규칙을 확인하지 못한 채 직접 설계한 구현입니다.
